# Residual function analysis

The symbol pass translated every name retained in the original ARM64 ELF, and
the reviewed callback and role pass added names only where the address and
behavior were checked. The final IDA inventory still has 418 address-only
`sub_` functions. This is expected for code that IDA discovered inside static
libraries, compiler-generated cleanup paths, and fixed init or fini arrays.

The complete address list and coarse classification are in
`artifacts/ida_final_residual_audit_20260830.json`. That report places 144
functions in the embedded FreeType region, 150 in the embedded JPEG region,
19 in init or fini array support, 102 in static cleanup wrappers or other
support, and one AArch64 PLT resolver slot. The count is a property of this
IDA database and the original library hash, not a claim that all 418 routines
are application code.

## Reviewed high-reference routines

The active IDA database was used to inspect a representative set of the most
referenced unnamed functions. The compact machine-readable record is
`artifacts/original_residual_semantic_review_20260830.json`, generated by

The arithmetic, stream, and identity helpers are referenced primarily as
function-pointer entries used by `TT_RunIns` at `0x2655e8` and the nearby
TrueType setup routine at `0x260050`. That relationship is stronger evidence
than a name guessed from one decompiler variable. The cleanup helper at
`0x250e94` is referenced from `FT_Done_Face` and performs object and driver
cleanup followed by allocator frees. The two string helpers are called from
the FreeType internal routine at `0x25a8e0`; their NEON loops normalize
printable diagnostic text and append a null terminator.

## Naming decision

These functions remain named by address. The review establishes their roles,
but it does not establish the exact upstream FreeType or TrueType source name
for every routine. Applying a plausible upstream name would make later source
matching harder if the bundled code contains local changes. A future name
should be added only after an exact source match, a verified function-pointer
slot, or a cross-version binary match supports it.

This pass is also not a vulnerability report. The selected routines are
embedded library internals, and their presence alone does not show that an
attacker controls their inputs. The broader image, font, archive, and network
input reviews remain the relevant security boundaries.
